# Browser-validation research history

Pre-final PSE Pulse browser-validation runs and corrective-action records are retained here for traceability. The initial run encountered intermittent navigation timeouts and a Firefox launcher failure. A separate pre-final regression later passed four of six categories; it was not a 100% browser-validation result.

The copied package under `2026-10-01-pre-final-validation/previous_active_package/` preserves the evidence that existed before the next validation effort. Its original 145-file manifest and later 526-file manifest both verified after copying. After intentional screenshot removal, the regenerated manifests cover 78 and 299 remaining files. Historical failure results remain part of the record.

The follow-up stability gate failed 8/12 configurations (116/120 visits passed). Its four failures were preserved. A subsequent 60-request HTTP probe, 80-attempt Chromium transport probe, and 40-logical-case targeted retry gate isolated intermittent no-main-document timeouts. The bounded policy permits one clean-context retry only for that failure type and records both attempts; it never replaces a performance trial. See `2026-10-01-pre-final-validation/transport_diagnosis/`.

The earlier final candidate passed 64/64 responsive cases and 76/80 (95%) five-second performance trials, with no performance retries. Chromium and WebKit compatibility passed, but isolated actual-Firefox WebDriver returned `unsupported operation` for two cases before a usable browsing context could be inspected; Firefox finished 14/16. These are not established application defects, but they were not eligible no-document retries either. That 5/6 candidate is retained as failed evidence, not rewritten or promoted.

The finalized acceptance scope is Chromium plus WebKit engine compatibility, 32 cases total. The project requirement specifies cross-browser compatibility but does not mandate Firefox. Firefox's earlier attempts and failures remain pre-final diagnostic evidence here; WebKit is not labeled Safari. A single fresh run under this clarified scope passed all six categories: responsive 64/64, cross-browser 32/32, 80/80 valid performance trials, and 78/80 (97.50%) within five seconds. One qualifying no-document responsive retry was retained; no performance trial was retried. The screenshot-pruned, verified 40-file package is active under `backend/research-result/system_testing/browser_validation/`, and the superseded active package is retained as `2026-10-01-pre-final-validation/superseded_active_20261001_1239_PHT/`. Automated browser validation does not replace stakeholder UAT.

Screenshots were intentionally excluded from repository storage to reduce repository size. Machine-readable CSV/JSON results and execution logs are the authoritative evidence. Screenshot path fields are blank; validation measurements and pass/fail results are unchanged.
